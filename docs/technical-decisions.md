# Technical Decisions

1. **pnpm workspaces over Turborepo**: Start simple. Turborepo can be added later if build orchestration complexity demands it.
2. **PostgreSQL Structured Retrieval over Pinecone/Qdrant**: Avoid premature vector DBs and external cloud dependencies. Use structured relational and JSONB schemas first, then evaluate `pgvector` for Phase 4.
3. **Deterministic Foundation Before AI**: Establishing verifiable repository facts (manifests, patterns, metrics) first prevents LLM hallucination and grounds any future AI explanations in actual code structure.
4. **No Blind Cloning**: Repository ingestion must be fast, bounded, and bandwidth-efficient, relying on GitHub REST APIs and metadata trees rather than cloning gigabytes of git history.
5. **Bounded Execution Guardrails**: Hard limits (10,000 tree items, 256 KB landmark previews) protect server memory and enforce predictable synchronous performance without requiring complex background queue infrastructure in early phases.
6. **No Auth Yet**: Deferred until persistent user-account features (e.g. personal bookmarking, saved notes) require it.
7. **Provider-Agnostic AI (`IAIProvider`)**: Abstraction in `apps/api` decoupling reasoning from model SDKs. Features Google Gemini (`gemini-3.8-flash` via `@google/genai`) and a zero-dependency deterministic `MockAIProvider` for 100% offline development, testing, and CI without API keys.
8. **Deterministic Post-Validation of AI Evidence (`EvidenceValidator`)**: Model-generated citations cannot be trusted unconditionally. Every citation returned by an AI provider is cross-checked against Phase 2 deterministic analysis facts (git tree, landmarks, dependencies, patterns, metrics) before persistence or client delivery.
9. **Snapshot-Keyed PostgreSQL AI Caching**: Caching explanations on `(repository_id, commit_sha, topic, target, prompt_version)` enables instant, zero-token replay. When a repository commit changes or prompts are revised, the unique index and cache layer cleanly isolate fresh analyses without requiring complex distributed cache invalidation logic.
10. **Prompt-Injection Defense with Delimiter Sanitization**: User-controlled repository text (README and description) is bounded to 2,000 characters and stripped of `<untrusted_content>` tags to prevent delimiter breakout attacks, then isolated in XML-style tags with strict system instructions.
11. **Server-Side Secret Isolation**: Credentials (`GEMINI_API_KEY`, `GITHUB_TOKEN`) are strictly consumed server-side in `apps/api`. They are never forwarded to `apps/web`, never bundled in Vite production assets, and never handled by `@archlens/shared`.
12. **Single-Database pgvector with Relational Fallback over External Vector DBs**: Rather than adding external vector databases (Pinecone, Qdrant, Milvus) or cloud dependencies, ArchLens retains a simple, single-database PostgreSQL architecture. Using dynamic capability detection (`hasPgVectorSupport`) and dual-mode storage (`embedding_vec vector(768)` and `embedding jsonb`), ArchLens executes native HNSW cosine distance search when `pgvector` is available and seamlessly falls back to exact in-memory vector cosine ranking when standard PostgreSQL is used, ensuring zero runtime crashes. The relational fallback is an intentional local development and graceful-degradation path, and is not equivalent to production pgvector retrieval.
13. **Line-Aware Chunking with Overlap over Full AST Parsing**: Line-aware chunking (50 lines per chunk, 10-line overlap) provides predictable chunk sizes, exact line range references (`startLine`, `endLine`) for source navigation, and universal language compatibility without pulling in heavy native tree-sitter grammars or requiring language-specific AST runtimes. Ingested repository code is never executed.
14. **Deterministic Mock Embedding Provider**: For offline development, automated CI suites, and environments without Gemini API credentials, `MockEmbeddingProvider` generates deterministic 768-dimensional normalized L2 vectors via token and n-gram hashing, allowing full end-to-end semantic retrieval and search ranking verification without network access. Retrieval quality under mock embeddings is not representative of production semantic quality; production evaluation requires real embeddings (Gemini) and pgvector.
15. **Zero-Dependency Tailwind Primitives over Heavy Component Libraries**: To maintain lightning-fast bundle times, zero external CSS runtime overhead, and strict architectural simplicity, Phase 5 avoids large external UI component libraries (e.g. MUI, Ant Design, Mantine). Instead, a dedicated set of accessible, composable UI primitives (`Button`, `Card`, `Badge`, `Input`, `Select`, `Skeleton`, `EmptyState`) was built directly on Tailwind CSS, standard DOM events, and Lucide React.
16. **Exclusion of Test Fixtures and Mocks from Landmark and Entrypoint Detection**: Test fixtures (e.g., `fixtures/**`, `__fixtures__/**`, `__mocks__/**`) contain sample applications or mock data that frequently include standard file names like `index.js` or `server.ts`. These must never be confused with production runtime entrypoints or key architectural landmarks. Hardening `detectLandmark` and `categorizePath` to categorize fixture directories as `'test'` and exclude them from entrypoint discovery ensures monorepos (such as `facebook/react`) correctly surface genuine package entrypoints (`packages/react/index.js`) rather than testing artifacts.
17. **Production AI Resilience with Multi-Tier Fallback, Bounded Latency Budget, Thinking Level Optimization, and Request Cancellation**: External AI APIs experience transient 503 outages ("high demand"), rate limits (429), or capacity bottlenecks. ArchLens implements a robust multi-tier resilience strategy: requests first target the primary model (`gemini-3.8-flash` via `GEMINI_API_KEY`) with bounded exponential backoff retries. If primary retries fail, requests route to a secondary model (`gemini-3.7-flash` via `GEMINI_FALLBACK_API_KEY`), and if that also fails, to a tertiary fallback model (`gemini-3.6-flash` via `GEMINI_TERTIARY_API_KEY`), providing an additional model/project fallback tier (without claiming guaranteed immunity against Google-wide capacity outages). Total worst-case latency is strictly bounded by an overall 18-second deadline budget (`totalBudgetMs = 18000`) and 6-second per-attempt timeouts (`perAttemptTimeoutMs = 6000`), guaranteeing responsive interactive failure handling (down from 28s). Thinking tokens are optimized with `thinkingConfig: { thinkingLevel: 'LOW' }` to eliminate 5–10s of internal reasoning delays on structured JSON generation. Fastify request abort signals are forwarded into `@google/genai` via `AbortController` to immediately terminate upstream sockets when clients disconnect or switch tabs. In the UI, per-topic state machines (`idle`, `loading`, `success`, `error`) and monotonic request sequencing eliminate race conditions, prevent stale error banners from coexisting with successful explanations, and support explicit cache bypassing via the Refresh control. Non-transient client errors (400, 401, 403, safety rejections) fail fast immediately without retries or fallback. All API credentials are systematically redacted from error messages, stack traces, and structured logs.
